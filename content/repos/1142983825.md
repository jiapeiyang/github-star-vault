## 它是什么
这个仓库把 Karpathy 对 LLM 编码常见问题的观察整理为一份 Claude Code 行为约定。核心内容是 CLAUDE.md 和相关 Skill/规则入口，围绕明确假设、保持简单、只修改直接相关范围和用可验证目标推进任务。

它提供的是编码代理的工作约定，不是代码分析器。文件本身不会静态检查 diff，也不会保证模型始终遵守规则；作用依赖宿主是否加载它，以及它与项目现有指令是否一致。

## 适合什么场景
编码助手经常扩展需求、增加无必要抽象或顺手修改无关代码时，可以用这里的规则作为比较材料。也适合团队检查自己已有的 AGENTS.md/CLAUDE.md 是否足够明确。已有成熟规则时，重点是吸收有用条款，而不是无条件叠加一整份文件。

## 如何开始
1. 阅读 README 的四项原则，并对应到当前项目的真实问题。
2. 查看 CLAUDE.md 的具体措辞，找出与已有约定重复或冲突的地方。
3. 选择项目规则文件或上游提供的插件方式接入。
4. 在一个范围明确的改动上观察 diff 和验证结果，判断是否需要调整。

README 的部分安装命令仍使用历史 owner `forrestchang`，应先确认跳转后的目标与当前仓库一致，不直接覆盖已有规则文件。

## 一个使用示例
假设任务只是修复按钮重复提交。可参考 Goal-Driven Execution，把任务描述改成：定位重复触发路径，定义一次点击只触发一次请求的验证方式，修改直接相关代码，并检查错误处理与恢复操作。

随后对照实际 diff 看是否新增了无关框架、是否改动旁边的功能。这个例子是基于仓库原则整理的说明性用法，不是本站已运行的编码实验，也不保证某种提示词必然获得更好结果。

## 注意事项与相关项目
README 将规则描述为偏谨慎的取舍，简单改字不一定需要完整工作流。名字表示受到 Karpathy 观点启发，不应理解成他本人维护的官方仓库。Cursor 用户可查看仓库中独立的规则与 CURSOR.md，不把 Claude Code 的目录约定直接照搬过去。
