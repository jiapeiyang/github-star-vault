## 它是什么
Git AI 在普通 Git 工作流上补充 AI 代码来源信息，记录代理、模型与相关提示上下文。提交后可查看 AI 归因统计，或用 AI blame 按行追溯，使后续维护能找回生成时的意图。

它追踪的是来源，不判断代码好坏。人修改过的 AI 代码、代理支持情况及归因保存方式都影响统计含义，不能把比例直接当成开发绩效。

## 适合什么场景
团队大量使用代理后需要解释某段代码如何产生；审查时找回提示背景；研究不同工具生成代码的保留情况。

## 如何开始
从 README 官方安装入口取得对应系统版本，确认所用代理在支持范围。随后按原有方式完成一个小任务并正常 commit，无需为每个仓库建立独立 Git hook。查看统计或在编辑器中使用归因插件，再检查提示记录与权限设置。

## 一个使用示例
官方命令改写，未执行：对已经记录归因并提交的文件运行 `git ai blame path/to/file`，预期逐行显示普通提交信息与代理归因。路径需替换为真实文件，安装之前的历史不会凭空拥有此前未采集的生成上下文。

## 注意事项与相关项目
README 描述提示存储在 Git 外并做脱敏，但仍应核对实际记录内容与共享范围。归因可能不完整，不能据此证明代码没有 AI 参与。它补充 Git 的来源记录，不替代代码审查或测试。
