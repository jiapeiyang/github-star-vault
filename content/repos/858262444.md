## 它是什么
awesome-cursorrules 收集 Cursor 项目规则，覆盖前端框架、后端、移动端、CSS、数据库、测试和部署。当前 README 使用 `.cursor/rules/` 下的 `.mdc` 格式，规则描述如何处理特定文件、技术栈和工作流。

这些文件是给代理的上下文约束，不会安装库或自动改变项目架构。价值在于减少重复说明，并让团队共享版本化的工程约定。

## 适合什么场景
新项目需要一份 React、Vue、Next.js 或 Python 的规则起点；已有团队想比对自己的 AI 指令遗漏；需要给特定文件范围附加安全或测试约定。

## 如何开始
从 README 分类找到与实际版本匹配的 `.mdc`，先阅读全文，再放进项目 `.cursor/rules/`。调整 `description`、`globs` 和 `alwaysApply`，删掉项目没有采用的库与目录假设。不同主版本规则可同时存在于合集，不能全部无差别复制。

## 一个使用示例
官方使用路径改写，未执行：一个 TypeScript 前端项目选取相应规则，限定到 `*.ts` 和 `*.tsx`，把其中的数据请求方式改成仓库已有方案，再让 Cursor 修改一处组件。预期代理能遵循本地约定；仍应检查 diff，确认没有引入规则模板里的无关依赖。

## 注意事项与相关项目
旧收藏名称中的 cursorrules 不代表当前仍以单一 `.cursorrules` 为主。规则不是静态分析器，描述有误会持续引导错误实现。与技能合集相比，项目规则更适合稳定、短小、按文件适用的约定。
