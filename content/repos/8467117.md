## 它是什么
node-xlsx 是基于 SheetJS xlsx 的工作表解析与生成封装，提供 parse 和 build 两个直接入口，并带 TypeScript 类型。输入可以是文件路径或 Buffer，生成时用工作表名称加二维数组表示内容。它适合在 Node 程序中读取或创建简单表格，不等同于操纵一个正在运行的 Excel 窗口。

## 适合什么场景
适合导入简单 XLSX 记录、导出报表，或给几个工作表配置列宽与合并范围。对复杂格式、公式计算和原文件完整保真应单独核实，不能从 parse/build 名称推断全部支持。

## 如何开始
按 README 安装 node-xlsx，ESM 用默认导入，CommonJS 示例为 require('node-xlsx').default。解析时给文件或 Buffer；构建时准备 [{name, data}]，需要列宽用 !cols，需要合并用 !merges 并确认起止行列索引。

### 本地验证：在内存中生成并重新读取工作表

复验时先按 Star Vault 源码中的 `docs/examples/v1.3/README.md` 安装独立依赖，再运行同目录的 `node-xlsx.mjs`。下文展示该完整测试的核心输入与结果；脚本不属于上游仓库。

环境：macOS arm64、Node.js 24.14.0、历史版 `node-xlsx 0.21.2`；这是明确固定的历史版本，不代表当前 0.24 的依赖组合。命令：`node node-xlsx.mjs`。

输入是一张 `Report` 表：

```js
const input = [{
  name: 'Report',
  data: [['Name', 'Count', 'Enabled'], ['Ada', 2, true], ['Lin', 0, false]],
}]
const buffer = xlsx.build(input)
const sheets = xlsx.parse(buffer)
```

实际得到 `Buffer.isBuffer(buffer) === true`。重新解析结果为：

```json
[{"name":"Report","data":[["Name","Count","Enabled"],["Ada",2,true],["Lin",0,false]]}]
```

断言比较了工作表名称、表头和每个单元格，`0`、`true`、`false` 都保留原类型。输入、XLSX Buffer 和解析结果全部在内存中，未读写用户文件。本例没有验证 Excel 显示、公式重算、复杂格式或不可信 XLSX 的处理能力。

## 注意事项与相关项目
重复合并同一单元格可能导致文件损坏，README 已明确提示。底层 SheetJS 决定很多单元格结构与格式能力，特殊对象需看其文档。README 的旧兼容章节不应覆盖实际 package.json 的运行要求；大文件的内存与处理时间也需要用真实规模验证。
