## 它是什么
diving-into-webpack 是八篇源码解析文章，先讲 Babel、CSS、图片等 Loader，再看 bundle 产物、编译流程、HMR 和 Tree Shaking。配套代码放在独立 my-webpack-loader 仓库，文章通过简化实现把配置项与底层执行过程联系起来。

## 适合什么场景
适合能写 Webpack 配置，但想知道 Loader 为什么组合、产物怎样运行，或维护历史构建工程时查原理。系列署名 2018，适合解释当时实现；使用新版本时要核对 Loader API 与插件生命周期差异。

## 如何开始
直接按 README 的相对链接阅读，不需要运行本仓库。可从 introduction 建立整体目标，再挑对应资源的 Loader；随后阅读 bundle.js 和 process-pipe-line。需要复现时才进入配套源码，固定其依赖版本并使用隔离目录。

## 一个使用示例
已查阅第三篇的示例，未执行：对 CSS 使用 style-loader 与 css-loader，文章解释 css-loader 处理 @import 和 url 依赖，style-loader 生成把样式插入 DOM 的运行代码。沿文中 pitch 与 require 的关系，区分构建时生成代码和浏览器执行代码。预期理解职责分工，而不只记数组顺序。

## 注意事项与相关项目
Loader 的执行与 pitch 有专门规则，简化示意应回到官方 Loader 文档确认。file-loader/url-loader 等旧路径在现代 Webpack 中可能有新替代，不能把 2018 配置当成最新建议。本文没有跑配套构建，也不保证旧版本在当前 Node 上直接可用。
