## 它是什么
oh-my-codex（OMX）保留 Codex CLI 作为执行引擎，为会话启动、项目规则、计划、日志和状态添加辅助机制。常用技能包含 plan、team、code-review、ultraqa 等，彼此可独立调用；资料保存在 .omx 中。它是第三方扩展，不是 Codex 官方发行渠道。

## 适合什么场景
适合使用终端版 Codex，并希望让多步任务有更明确的工作流与状态记录的人。README 推荐 macOS 或 Linux 加 Codex CLI；原生 Windows 和 Codex App 不是默认支持体验，不能假定桌面应用里能完整运行所有功能。

## 如何开始
先确认 `codex --version` 可用且已登录，再 `npm install -g oh-my-codex`。已有 Homebrew 管理的 Codex 不要为 OMX 重复安装另一份同名二进制。项目级设置应在实际仓库中执行，并明确 AGENTS 合并策略；用户级设置用单独 scope。阅读 setup 变更后，再在该项目调用需要的技能。

## 一个使用示例
说明性示例，未执行：在一个已存在的 Git 项目里，使用 `$plan` 明确搜索改动，再在实现分支用 `$code-review` 检查，最后以 `$ultraqa` 对验收条件做验证。预期得到范围明确的计划和证据。是否使用 team、创建工作树或更宽执行权限应由实际任务决定，不必照抄 README 的全套启动标志。

## 注意事项与相关项目
setup 可能写入项目 AGENTS.md，宽泛的 home 目录不应误当项目根。官方仓库与 npm 包名是本条来源，名称类似的“OMX v2”不能自动视为继承版本。自动更新和持久合并策略也会影响之后的会话，应在启用前了解当前版本行为。
