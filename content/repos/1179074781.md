## 它是什么
botmux 的 daemon 监听飞书消息，每个新会话启动独立 CLI 进程，再把输出同步到卡片和可交互 Web 终端。它复用已有 Claude Code、Codex 等工具，不另写一套模型 Agent。

会话、机器人与工作目录共同决定任务在哪运行；多个机器人可以在同一群内承担不同角色。手机控制只是消息入口，实际代码和命令仍在开发机执行。

## 适合什么场景
离开电脑后查看代理进度或补充指令；把群里的授权任务接到指定仓库；希望不同 CLI 对同一问题独立给出意见。

## 如何开始
按平台安装自包含二进制，Windows 当前走 WSL2。准备已可运行的编码 CLI，在 `botmux setup` 中选择飞书应用、CLI 和工作目录，再启动 `botmux start`。README 的自动设置可能配置权限并发版；若需要手动处理，可选择 `--no-open-platform-auto`，再按文档完成。

## 注意事项与相关项目
群成员可见范围和机器人操作权限要与代码库匹配，可写 Web 终端尤其要限制访问。跨群 relay 可能改变信息受众，不能默认转发。Herdr 更偏终端内组织，botmux 更偏飞书遥控桥接。
