## 它是什么

Monid 平台面向代理提供工具发现、检查和执行；这个仓库主要是它的连接器层。Provider 描述服务身份、认证与用量，Endpoint 描述一次调用的输入、请求及输出约束，编译后由统一引擎执行。

## 适合什么场景

- 希望为代理接入一个有明确文档的 API，并把参数与返回值约束保留在代码中。
- 想用录制响应做回放测试，避免日常 CI 必须依赖真实供应商密钥。
- 需要理解工具路由平台与具体连接器实现之间的边界。

## 如何开始

1. 准备 Deno 2.x，读取 README Quickstart 和 `connectors/exa/` 参考实现。
2. 先浏览目录与一个端点契约，再研究 Provider、Endpoint 和 fixture 的对应关系。
3. 本地检查采用 `deno task check` 与 `deno task test`；真实调用需要供应商凭据，和无网络回放测试分开。

## 一个使用示例

官方命令摘录，未执行：在项目目录查看 Exa 搜索端点的声明。

```sh
deno task catalog inspect 'exa#search'
```

预期输出是端点输入、输出等契约资料，便于判断是否适合当前任务；这不是执行搜索，也不会证明供应商此时可用。本文没有安装 Deno 依赖或调用任何付费工具。

## 注意事项与相关项目

仓库连接器、托管平台与外部供应商是不同层。README 宣传的工具数量、健康状态和费用需以实际调用时信息为准。密钥注入方式和费用规则是项目实现说明，不构成第三方服务的安全或价格保证。
