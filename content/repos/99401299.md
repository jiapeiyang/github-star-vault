## 它是什么
Nano ID 是 JavaScript 的随机字符串 ID 生成器。默认生成 21 个字符，使用适合 URL 的字符集合，可用来标记应用中的记录、临时对象或资源。它通过运行环境的加密随机能力产生随机字节，并关注字符分布的均匀性。

它提供的是随机标识符，不是按时间排序的序号，也不是数据库主键约束的替代品。业务仍需决定何时生成、在哪里保存，以及出现重复时由哪一层处理。缩短长度或缩小字符集合会改变碰撞概率。

## 适合什么场景
- 新建记录时需要一个简短、可放进 URL 的 ID。
- 多个客户端各自生成标识，之后再提交到服务端。
- 演示数据或临时对象需要可区分的名称，但不要求编号连续。

如果系统已有数据库自增 ID 且无需客户端提前生成标识，未必需要再增加一套随机编号。

## 如何开始
1. 在项目中安装 `nanoid`，核对所用版本及模块格式说明。
2. 在支持 ESM 的文件中导入 `nanoid`。
3. 在创建记录时生成一次并保存；随后复用这个已保存的 ID。
4. 确实需要自定义字符集或长度时，再查看 `customAlphabet` 和碰撞概率说明。

```shell
npm install nanoid
```

### 本地验证：创建记录后保留 ID

复验时先按 Star Vault 源码中的 `docs/examples/v1.3/README.md` 安装独立依赖，再运行同目录的 `nanoid.mjs`。下文展示该完整测试的核心输入与结果；脚本不属于上游仓库。

环境：macOS arm64、Node.js 24.14.0、`nanoid 6.0.1`。命令：`node nanoid.mjs`。v6 的 Node 支持范围为 22、24 或 26+；更早环境应选择相应历史版本。

输入是一条标题为 `Cache guide` 的记录。用默认生成器创建一次 ID，修改标题后复用该 ID；再生成一个 10 位十六进制标识：

```js
import { nanoid, customAlphabet } from 'nanoid'
const bookmark = { id: nanoid(), title: 'Cache guide' }
const stableId = bookmark.id
bookmark.title = 'HTTP cache guide'
const shortId = customAlphabet('0123456789abcdef', 10)()
console.log(bookmark, bookmark.id.length, bookmark.id === stableId, shortId)
```

本次实际记录的 ID 为 `fOgvC9ps6yiv8PDoBIgPY`，长度 `21`；标题更新为 `HTTP cache guide`，ID 保持判断为 `true`。十六进制结果为 `b91de94a7d`，长度 `10`。这些是一次运行的随机结果，再运行时字符串应不同；断言检查长度、字符集合和复用行为，不检查固定 ID，也不证明永无碰撞。

## 注意事项与相关项目
默认安全随机源与 `nanoid/non-secure` 是不同入口，不能在需要不可预测标识的场景里随意替换。React 列表的 key 应来自稳定的数据标识；每次渲染都重新调用随机生成器会改变 key。仓库还提供 UUID 对比，但上游某台机器的性能数字不能直接当作你的项目实测。
