## 它是什么
Nano ID 是 JavaScript 的随机字符串 ID 生成器。默认生成 21 个字符，使用适合 URL 的字符集合，可用来标记应用中的记录、临时对象或资源。它通过运行环境的加密随机能力产生随机字节，并关注字符分布的均匀性。

它提供的是随机标识符，不是按时间排序的序号，也不是数据库主键约束的替代品。业务仍需决定何时生成、在哪里保存，以及出现重复时由哪一层处理。缩短长度或缩小字符集合会改变碰撞概率。

## 适合什么场景
- 新建记录时需要一个简短、可放进 URL 的 ID。
- 多个客户端各自生成标识，之后再提交到服务端。
- 演示数据或临时对象需要可区分的名称，但不要求编号连续。

如果系统已有数据库自增 ID 且无需客户端提前生成标识，未必需要再增加一套随机编号。

## 如何开始
1. 在项目中安装 `nanoid`，核对所用版本及模块格式说明。
2. 在支持 ESM 的文件中导入 `nanoid`。
3. 在创建记录时生成一次并保存；随后复用这个已保存的 ID。
4. 确实需要自定义字符集或长度时，再查看 `customAlphabet` 和碰撞概率说明。

```shell
npm install nanoid
```

## 一个使用示例
以下根据官方 API 编写，用于解释“创建一次、保存后复用”，未执行：

```js
import { nanoid } from 'nanoid'

const bookmark = {
  id: nanoid(),
  title: '待整理的链接',
}

console.log(bookmark.id, bookmark.id.length)
```

在采用默认配置的版本中，预期看到一个 21 字符随机 ID 和长度 `21`，每次运行的字符串不同。若放在 Node.js 中，可将示例保存为 `.mjs` 文件后运行。不要把某次示例字符串当作固定输出。

## 注意事项与相关项目
默认安全随机源与 `nanoid/non-secure` 是不同入口，不能在需要不可预测标识的场景里随意替换。React 列表的 key 应来自稳定的数据标识；每次渲染都重新调用随机生成器会改变 key。仓库还提供 UUID 对比，但上游某台机器的性能数字不能直接当作你的项目实测。
