## 它是什么
Ponytail 是一组编码代理规则、技能和宿主适配，不是代码压缩器。它要求代理理解代码调用关系后，依次判断需求是否必要、仓库是否已有能力、标准库和原生平台是否足够，最后才增加最小实现。

核心目标是减少过度设计，而不是强制把代码写成一行。README 明确要求保留权限边界校验、数据丢失处理、安全和可访问性。不同宿主的插件还可通过 hooks 在会话或代理调用时注入当前规则级别。

## 适合什么场景
- AI 经常为简单表单控件引入新组件库和包装层。
- 改动需要复用当前项目约定，但代理倾向重新搭框架。
- 希望给已有工程做简化评审，同时保留真实边界处理。

## 如何开始
从 README 选择实际使用的宿主安装方式，避免混用不同客户端命令。也可以先阅读仓库规则，再选相应 rules 文件用于单一项目。Claude Code 与 Codex 插件的生命周期 hooks 需要 Node.js 在非交互 shell 的 PATH 中；缺少 Node 时技能内容与自动激活不是同一回事。安装后通过 `/ponytail` 选择级别，并用小改动检查规则是否适合项目。

## 一个使用示例
官方示例改写，未执行：需求只是一个日期输入框，且没有自定义日历交互要求。代理先确认浏览器原生能力是否满足，再考虑：

```html
<input type="date">
```

预期减少额外依赖和包装组件，但标签、必填约束与日期业务校验仍由具体表单负责。若必须展示复杂日期范围或品牌日历，不能为了少代码忽略需求。

## 注意事项与相关项目
README 的代码量、费用和耗时数据有指定模型、任务集和基线，不代表所有工程都得到相同比例收益。全局启用会影响多个任务，适合先在项目范围试用。它约束实现取舍；superpowers 更侧重完整开发流程，两者是否合用要看规则是否冲突。
