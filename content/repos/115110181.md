## 它是什么
SWC 是 Speedy Web Compiler，既提供 Rust 编译组件，也通过 @swc/core、CLI 等入口供 JavaScript 工具使用。它将源文件解析成语法结构，再按配置做转换与代码生成；很多开发工具会把它作为内部编译环节。语法转换与完整应用打包是不同职责。

## 适合什么场景
适合需要加速源文件转换、在工具中接入 JavaScript 解析，或评估 Babel/TypeScript 转译环节替代方案的项目。迁移时应先列出当前插件、模块格式和目标浏览器，不能只替换包名就假定输出语义完全一致。

## 如何开始
官方 CLI 文档示例是 `npm install -D @swc/cli @swc/core`。先选择一份小的 JavaScript 文件，按 .swcrc 配置目标和模块行为，再用 CLI 转换。Rust 用户应从 rustdoc 与 parser 入口阅读，不直接沿用 Node 包安装流程。

### 本地验证：去除 TypeScript 标注并执行转换结果

复验时先按 Star Vault 源码中的 `docs/examples/v1.3/README.md` 安装独立依赖，再运行同目录的 `swc.mjs`。下文展示该完整测试的核心输入与结果；脚本不属于上游仓库。

环境：macOS arm64、Node.js 24.14.0、`@swc/core 1.16.2`，使用 npm 提供的对应平台原生包。命令：`node swc.mjs`。

输入：

```ts
const price: number = 12; console.log(price * 2);
```

转换调用：

```js
const { code } = transformSync(input, {
  filename: 'example.ts',
  jsc: { parser: { syntax: 'typescript' }, target: 'es2022' },
})
```

实际生成的 JavaScript 为：

```js
const price = 12;
console.log(price * 2);
```

脚本只执行上面这一行自写示例的编译结果，捕获输出 `[24]`；还检查了 `: number` 已移除。本例验证类型语法转换和该表达式的结果，没有验证类型正确性、其他 Babel 插件、整个应用打包或旧浏览器兼容性。

## 注意事项与相关项目
README 的最低 Node 与 Rust 版本是所查快照，不一定覆盖所选包的每个版本。转译不等于 TypeScript 项目的完整类型检查；应用仍需自己的类型验证与测试。SWC 与 Babel 的插件体系不同，迁移前按官方比较文档核对实际能力。
