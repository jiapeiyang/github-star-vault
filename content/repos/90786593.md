## 它是什么
TypeScript Vue Starter 是 Microsoft 留下的一份 Vue 与 TypeScript 手工集成示例。它按步骤介绍如何配置 TypeScript、Webpack、loader，再构建 Vue 页面与组件，适合理解较早 Vue 工程的组成方式。

仓库开头明确说明该项目已废弃，保留它的目的在于历史参考。文中存在 Vue 2 风格的 `new Vue(...)`、旧 loader 组合等内容，因此应把它当成旧工程的解释材料，而不是当前新项目的默认脚手架。

## 适合什么场景
- 接手 Vue 2 与 Webpack 的旧项目，需要理解配置之间的关系。
- 想知道 TypeScript 文件、Vue 模板和打包入口是如何接在一起的。
- 对照历史工程方式与当前官方方案，辨认哪些配置属于工具链演进的产物。

如果目标是创建当前 Vue 应用，应从 Vue 官方网站的最新文档开始，不要因为这个仓库由 Microsoft 发布就直接套用它的历史依赖。

## 如何开始
1. 先阅读顶部 deprecated 说明，确认接受历史示例范围。
2. 按 README 的 TypeScript configuration、Adding Webpack、Create a basic project 顺序看配置。
3. 重点对照 `src/index.ts`、`tsconfig.json`、Webpack 配置与根目录 HTML 之间的引用关系。
4. 如需复现，使用隔离目录，按仓库版本核对依赖；不要直接在现有工程中安装文中未锁定的旧组合。

## 一个使用示例
README 的基础例子在 `src/index.ts` 中创建 Vue 实例，把初始 `name` 设置为 `World`，模板中同时渲染 `Hello {{name}}!` 和一个 `v-model="name"` 输入框。

按该历史工程完成构建配置后，文档给出的命令是：

```shell
npm run build
```

打开根目录 `index.html`，预期显示 Hello World，改变输入框文字时问候文本一起变化。这个例子用于观察“类型脚本入口—打包输出—HTML 加载—响应式绑定”的关系；本站仅核对了 README，没有复现旧依赖环境。

## 注意事项与相关项目
README 提及的“官方 CLI”同样属于文档写作时的建议，不能据此推断它仍是今天的首选。最新建项目方式请查当前 Vue 文档。旧示例的价值在解释历史项目，不在证明其依赖目前无风险或可以无修改安装。
