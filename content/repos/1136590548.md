## 它是什么
ECC 是从编码配置扩展而来的工程工具集合，覆盖技能、代理、命令、Hooks、上下文与跨宿主适配。当前版本还提供本机 Plan Canvas，让用户在浏览器中对计划逐处标注，并把批准或修改意见回传到规划流程。开源工具与托管 GitHub App 是不同交付形态。

## 适合什么场景
适合想改善计划评审、代码审查、构建修复或会话交接的团队。README 建议从当前工作需要出发，而不是载入全目录。只需规划时可先试 plan，现有项目已经有充分 Hooks 时则要避免重复执行。

## 如何开始
Claude Code 的官方推荐入口是 `npx ecc-universal@2.2.1 setup`，要求 Node.js 18+、Git 与 Claude Code 2.1+，设置会记录所选范围与 Hook profile。也可选择原生插件安装，但不要再叠加完整手工安装。其他宿主从相应章节进入，先确认冲突、更新与卸载行为。

## 一个使用示例
官方示例改写，未执行：使用 `/ecc:plan "Add authentication"` 形成计划，在 Plan Canvas 对不明确的登录状态和错误路径加注释，选择 Request changes 让代理修订。预期是形成经过确认的计划后再实施，而不是打开画布就默认批准代码改动。

## 注意事项与相关项目
配置审计、重构清理与托管 App 可能触达不同文件和外部权限，需按实际任务区分。当前 README 已将统一资料库列入 2.2 发布摘要；旧的 current development 标注不再代表现行状态，实际安装仍需核对发行版本与宿主支持。模型服务、GPU 计算和私有仓库托管的价格是独立事项，不由 MIT 仓库许可覆盖。

setup 面向 Claude Code，跨 Claude Code、Codex、Kimi Code 使用 install --guided，并先检查目标路径与 dry-run。需要 Hooks 的安装须明确选择启用或禁用。/security-scan 只是工作流入口，实际扫描还需单独安装并核对 ecc-agentshield；不能把固定安装版本当成完成安全审计。
