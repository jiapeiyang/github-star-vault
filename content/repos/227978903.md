## 它是什么
VueUse 是围绕 Vue Composition API 编写的一组可组合工具函数。它把鼠标坐标、浏览器存储、系统偏好等常见状态接到 Vue 的响应式系统中，让组件能直接消费这些状态，而不必重复维护事件监听和状态同步代码。

可以把它理解成一个按功能检索的工具库：先确定你需要读写的浏览器能力，再找到对应的 `use...` 函数。它不是 UI 组件库，调用函数不会自动生成页面；页面结构和交互仍由你的 Vue 组件负责。

## 适合什么场景
- 为 Vue 页面读取鼠标位置、窗口信息或系统深色模式偏好。
- 将一个小范围的页面设置持久化到 localStorage。
- 在多个组件间复用常见浏览器交互逻辑，并保持 TypeScript 类型提示。

如果需求只是展示一个按钮或表单，应先选 UI 组件；VueUse 解决的是背后的状态与副作用。

## 如何开始
1. 检查 Vue 版本。当前 README 明确说明：VueUse v14 需要 Vue 3.5+，v13 需要 Vue 3.3+，Vue 2 项目应查看 v11 系列。
2. 在已有 Vue 项目中安装 `@vueuse/core`。
3. 从函数目录按能力查找工具，先查看参数、返回值和官方演示。
4. 在组件 setup 中调用需要的函数，将返回状态接入模板；需要额外集成时再查看 add-ons。

```shell
npm i @vueuse/core
```

## 一个使用示例
### 原示例（未执行）
以下是官方 README 中 localStorage 示例的简化改写，未在本站运行：

```ts
import { useLocalStorage } from '@vueuse/core'

const settings = useLocalStorage('reader-settings', {
  name: 'Apple',
  color: 'red',
})

settings.value.color = 'blue'
```

预期用途是把 `reader-settings` 对应的对象作为响应式状态使用，并让修改与浏览器存储同步。键名应根据你的应用自行选择；这不是跨设备同步，也不应存放秘密。验证时可以查看浏览器存储，并在刷新后确认值是否恢复。

### 本地验证：受上下限约束的计数器

复验时先按 Star Vault 源码中的 `docs/examples/v1.3/README.md` 安装独立依赖，再运行同目录的 `vueuse.mjs`。下文展示该完整测试的核心输入与结果；脚本不属于上游仓库。

环境：macOS arm64、Node.js 24.14.0、`@vueuse/core 14.4.0` 与 `vue 3.5.42`。命令：`node vueuse.mjs`。这个例子选择不依赖浏览器的 `useCounter`，与上面未执行的 localStorage 例子分开。

```js
const { count, inc, dec, set, reset } = useCounter(1, { min: 0, max: 3 })
const values = [count.value]
inc(5); values.push(count.value)
dec(10); values.push(count.value)
set(2); values.push(count.value)
reset(); values.push(count.value)
```

输入初值 `1`、范围 `0–3`，实际顺序输出为：

| 操作 | count.value |
| --- | --- |
| 初始化 | 1 |
| inc(5) | 3 |
| dec(10) | 0 |
| set(2) | 2 |
| reset() | 1 |

超过上限时停在 `3`，低于下限时停在 `0`，无参数 reset 恢复初值。这只验证计数器 API 与本组边界，不表示浏览器存储、事件监听或刷新恢复已经验证。

## 注意事项与相关项目
SSR Friendly 不代表每个浏览器能力都能在服务端取得真实值，应查具体函数的生命周期和回退说明。接入旧 Vue 项目时尤其要核对版本，不要直接复制最新文档到不兼容的依赖组合。仓库 README 提到 React 侧的 react-use 等相关项目，但 API 不能直接互换。
