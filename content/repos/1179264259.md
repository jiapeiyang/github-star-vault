## 它是什么
gstack 是 Garry Tan 维护的编码代理技能与工具集合。它把产品、工程、设计、QA 和发布职责拆成独立命令，并让前一步产物供下一步读取，例如产品讨论形成设计文档，工程评审补充测试计划，浏览器 QA 检查实现。核心是过程约束加工具，不是单独运行的新模型。

## 适合什么场景
适合已有代码库但希望加强需求澄清、分层审查和浏览器验证的个人或团队。可以只使用 `/review` 或 `/qa-only` 解决一个问题，不必把所有角色都加入每次改动。发布相关命令涉及真实 Git 和部署动作，应在具体任务允许时使用。

## 如何开始
当前 README 的基础要求为 Claude Code、Git、Bun 1.0+；Windows 还需要 Node.js。先阅读安装脚本与宿主说明，再按仓库 setup 流程安装。macOS 推荐的 Aside 是可选浏览器路径，缺少时有仓库自带浏览器。安装完成后先用 `/office-hours` 描述实际问题，或在已有改动分支上运行 `/review`，熟悉产物再扩展流程。

## 一个使用示例
官方流程改写，未执行：给一个“日历每日简报”的想法，先用 `/office-hours` 解释目前哪些准备工作耗时，再用 `/plan-eng-review` 检查数据流与测试矩阵。实现后对测试 URL 运行 `/qa-only` 获得问题报告。预期得到可核对的设计、评审和页面证据；测试通过与是否发布是两个独立决定。
