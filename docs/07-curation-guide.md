# v1.1 策展与笔记操作指南

## 找到项目

- 项目库支持搜索仓库描述、个人价值说明和完整笔记正文。
- 收件箱分为新收藏和历史待整理，每页 30 条，可用队列搜索缩小范围。
- 手机端点击“选择其他项目”跳转到队列，选择后用“回到整理表单”返回。
- 收藏、分类和学习阶段来自已发布数据；在页面里编辑不会立即改变这些统计。

## 新建一份策展文件

1. 在收件箱选择项目，或从项目详情点击“整理此项目”。
2. 选择主分类和资源类型，填写自己的“一句话价值”，选择真实学习阶段。
3. 添加最多 5 个标签，每个标签单独填写；语言已有字段，不重复添加。
4. 在 Markdown 正文中写学习结论、实践记录和链接。点击“阅读预览”检查排版。
5. 点击“下载策展文件”，得到 `<repo_id>.md`；也可以复制 Markdown。
6. 把文件放到仓库 `content/repos/` 下。如果浏览器给同名下载加了 `(1)` 等后缀，放入仓库前恢复为数字 repo_id 文件名。
7. 审阅文件内容与 Git diff，确认后提交并推送。Actions 成功后网站更新。

下载提示表示已发起浏览器下载，文件是否保存在 Downloads 等目录由浏览器管理。复制成功也不表示已写入 GitHub。

## 修改已有记录

从详情点击“编辑策展文件”，或者从学习页点击“编辑学习记录”。表单回填已有分类、阶段、标签、一句话价值和完整正文。

关联项目在本版只读，导出会保留原 repo_id 数组。需要修改关联时直接编辑 Git 文件。个人归档或已退出公开 Stars 的项目仍可打开编辑入口，笔记不会因取消 Star 而丢失。

无修改直接导出时保留原个人更新时间；有实际修改时使用当前浏览器所在时区的日期。TOML 的排版与注释可能改变，正文和已支持字段保持内容语义。文件出现本版不支持的元数据时，表单禁止导出，提示使用 Git 文件编辑。

## 写一份可阅读的笔记

```markdown
## 学习结论

- 写下实际阅读或实践形成的具体结论。

## 实践记录

1. 做了什么。
2. 看到了什么结果。

[官方资料](https://example.com/)
```

支持标题、段落、强调、嵌套列表、引用、行内代码和围栏代码块。长代码在代码块内横向滚动。

页内链接示例为 `[学习结论](#学习结论)`；标题空格转为连字符、英文字母转小写，相同标题的后续锚点追加 `-1`、`-2`。正文实际标题 id 使用 `note-` 前缀，链接会自动转换。

网页不执行 Markdown 中的 HTML，不将危险协议或相对文件路径变成可点击链接。图片显示文字占位，不自动加载。表格、数学公式和图表不属于本版支持范围。

只有“学习结论”下有非占位内容时，才能导出 `learned`。校验能识别空内容和常见占位语，无法判断结论是否真的来自你的实践，仍需要人工确认。

## 本地校验与发布

在项目根目录执行：

```bash
python3 scripts/verify_data.py
python3 scripts/build_catalog.py
python3 scripts/generate_readme.py
npm --prefix app test
GITHUB_PAGES=true npm --prefix app run build
npm --prefix app run test:sites
git diff --check
```

检查 `git diff -- content/repos README.md` 后，提交本次实际修改的文件并推送到 main。进入 GitHub Actions 查看运行结果；成功后刷新公开网站，确认详情、分类和学习阶段。

同步脚本不修改 content/repos；下载文件也不能直接放进 data/ 或 app/public/data/，这些是生成目录。

## 草稿与未处理场景

未导出的修改在切换项目、离开页面或刷新时会提醒。取消离开可以继续编辑；成功复制或发起下载后清除提醒状态。浏览器可能限制刷新/关闭时的提醒文字。

草稿只在内存中，不保证强制退出、崩溃或跨设备恢复。多设备修改由 Git 差异审阅和冲突处理解决。本版没有在线保存、自动合并或后台草稿同步。
