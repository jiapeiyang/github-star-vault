## 它是什么
Uptime Kuma 是自托管监控工具，可定时执行 HTTP(S)、关键词、JSON 查询、TCP、WebSocket、Ping、DNS、Push 和 Docker 等检测，保存历史并通过通知渠道告警。它还能为选定服务建立状态页。

## 适合什么场景
监测自己的网站、API 或服务入口是否可访问，查看中断时段与证书信息。结果体现监测节点的视角；一个节点返回正常，不表示所有用户、地区或业务步骤均正常。

## 如何开始
按 README 选择 Docker Compose、容器或非 Docker 安装。当前示例使用 `louislam/uptime-kuma:2` 和本地持久卷 `/app/data`；上游明确不支持 NFS 等网络文件系统。非 Docker 路线另需满足 Node.js、平台与进程管理要求。

默认容器端口映射会暴露所有网卡，只需本机访问时应按文档限制到 `127.0.0.1`。先配置管理员、备份和一个测试监控，再决定是否开放状态页与真实通知。

## 一个使用示例
场景示例，未执行：为自己管理的健康检查 URL 新建 HTTP 监控，明确成功状态码和检查间隔；在测试环境短暂停止后端，检查是否记录中断与恢复。通知测试可能真正发送消息，应先选定接收方并获得授权。

## 注意事项与相关项目
仅探测首页状态码可能漏掉登录、数据库或支付等业务失败，应按服务目标选择探测内容。监测机与被测服务同时故障可能让告警失效；不要把本工具当成独立外部监控保障。状态页还需检查暴露的内部名称和地址。

Caddy 可为应用提供反向代理与 HTTPS 入口，监控工具负责观察，二者不互相替代。升级特别是跨主要版本前应阅读更新文档并备份实际数据。
