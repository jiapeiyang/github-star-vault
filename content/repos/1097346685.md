## 它是什么
Impeccable 用一个技能承载多种前端设计命令，包括 init、shape、audit、critique、polish 和 distill。当前 README 还包含确定性检测规则与 live 浏览器迭代，用来发现常见的 AI 界面模式和实际质量问题。

它把产品事实与视觉规则分别记录：`PRODUCT.md` 保存用户、用途和限制，`DESIGN.md` 描述视觉系统。这样后续修改不必每次从一个笼统的“好看”要求重新开始。

## 适合什么场景
给已有页面做层级与可访问性检查；在功能稳定后统一间距和组件细节；让代理在固定产品目标下持续改进界面。

## 如何开始
在项目根目录运行 README 的 `npx impeccable install`，选择宿主与项目/全局范围，重新加载工具。先用 `/impeccable init` 建立产品背景，再选择具体命令；Codex 需按宿主界面处理 hook 信任。安装工作文件和共享设计资料应按文档区分提交范围。

## 一个使用示例
官方命令改写，未执行：运行 `/impeccable audit the header` 检查页头，读取问题与截图证据后，再用 polish 聚焦搜索框对齐、焦点和窄屏表现。预期是有范围的修改与复核，而不是顺手重做整站视觉。

## 注意事项与相关项目
规则检测可以找确定模式，审美与任务适配仍需判断。不同版本命令和 hooks 会变化，应以当前 README 为准。它从 frontend-design 扩展出完整流程，不能替代产品需求与真实浏览器验证。

当前安装器会带入独立引擎程序；Node.js 用于 npx 安装入口，不应据此推断引擎始终依赖 Node 运行。安装范围与 hooks 信任需按宿主确认，不需要 hooks 时可选择 `--no-hooks`。需要关闭遥测时查看 `IMPECCABLE_NO_TELEMETRY` 或 `DO_NOT_TRACK` 配置。

live 模式面向本地开发服务，会参与页面迭代；不要把其注入方式直接用于生产站点。只观察线上页面时，README 提供 `detect URL` 的只读检测入口。检测结果与本站实测分开，本页没有执行这些命令。
