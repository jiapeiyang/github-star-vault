## 它是什么
Svelte 允许在 .svelte 组件中组织模板、脚本和样式，再由编译器生成用于更新 DOM 的 JavaScript。它把一部分传统运行时工作放到构建阶段，组件可以独立嵌入页面，也可结合 SvelteKit 构建带路由与服务端能力的应用。

## 适合什么场景
适合喜欢接近 HTML/CSS 的组件表达，或想比较编译式框架与 JSX 路线的人。Svelte 核心关注组件，完整应用的路由、加载和部署通常属于 SvelteKit 等上层工具，选型时应分开确认。

## 如何开始
官方 Overview 推荐新用户先打开交互教程或 Playground，无需安装。试本地工程时从 Getting started 选择应用路径，再按对应版本的 CLI 创建。当前文档将 Runes 与 Legacy APIs 分列，旧教程的事件和状态语法不应与新示例混用。

### 本地验证：组件编译后的服务端 HTML

复验时先按 Star Vault 源码中的 `docs/examples/v1.3/README.md` 安装独立依赖，再运行同目录的 `svelte.mjs`。下文展示该完整测试的核心输入与结果；脚本不属于上游仓库。

环境：macOS arm64、Node.js 24.14.0、`svelte 5.57.0`。命令：`node svelte.mjs`。输入组件为：

```svelte
<script>let { name, count } = $props();</script>
<p>Hello {name}; total: {count * 12}</p>
```

脚本用 `svelte/compiler` 的 `compile(source, { filename: 'Greeting.svelte', generate: 'server' })` 编译，加载自写组件产物，再用 `svelte/server` 的 `render(Greeting, { props: { name: '<Ada>', count: 2 } })` 生成 HTML。

实际 `body` 为：

```html
<!--[--><p>Hello &lt;Ada>; total: 24</p><!--]-->
```

编译警告数为 `0`。`<Ada>` 中的 `<` 被转义，因此作为文本插值保留；`>` 在本次输出中保持原字符。前后注释是此版本生成的标记。临时编译文件在 finally 中清除。本例验证编译和服务端字符串渲染，没有启动 Web 服务，也没有验证按钮事件、浏览器 hydration 或全应用安全性。

## 注意事项与相关项目
资料中能看到 Svelte 4、Svelte 5 的迁移入口，旧文章需要明确版本。编译成功不证明可访问性、业务状态或服务端行为正确。Solid 同样追求精细 DOM 更新，但采用 signal 与 JSX，阅读两者时应关注更新模型而不只比较语法长度。
