## 它是什么
New API 是模型 API 网关及管理系统，在客户端和多个上游服务之间统一认证、模型路由与用量记录。管理界面提供用户、令牌分组、模型限制、配额和费用配置；后端按渠道转发请求。它可兼容多种模型协议，但每种转换方向的支持范围不同。

## 适合什么场景
适合团队共享多个模型渠道、限制不同应用可用模型，或把用量按用户与项目核算。它需要真实上游授权和运行数据库，增加一层网关也意味着需要维护服务可用性、模型映射与费用规则。

## 如何开始
README 推荐取得仓库后编辑 docker-compose.yml，再通过 Docker Compose 启动，默认访问 localhost:3000。先核对端口与持久化目录，在初始管理界面配置用户与渠道，再创建限额令牌给客户端使用。只验证一个上游和模型后，再增加其他渠道，便于区分网络、认证与格式问题。

## 一个使用示例
说明性示例，未执行：为内部文档助手配置一个可用模型渠道，发放只允许该模型的调用令牌，再用一条短请求检查响应，在控制台核对记录及额度变化。预期是调用经过受控入口；网关显示的成本还取决于配置的计费倍率和上游实际账单，不能直接等同财务结算结果。

## 注意事项与相关项目
README 标记 Gemini 到 OpenAI 的部分转换仅支持文本、尚不支持 function calling，Responses 双向转换也有开发中项目。不能把支持接口名理解为所有高级字段无损兼容。数据卷保存配置和业务记录，升级前应确认备份与版本。CLIProxyAPI、Aether 可作为不同管理侧重点的对照。
