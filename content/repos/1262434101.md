## 它是什么
该仓库将账号注册流程组织为 Python 状态机，并提供邮箱接口与 WebUI，用于查看任务状态、日志和产生的凭据。README 描述了无浏览器协议请求、邮箱验证码处理及多任务管理。它处理真实第三方账号和认证材料，不能理解为通用的离线表单示例。

## 适合什么场景
对于收藏回顾，价值在于理解注册流程如何拆成阶段、邮件提供方如何抽象，以及 UI 怎样展示 available、in_use、done、failed 等状态。涉及真实平台的批量注册、风控或验证码规避不属于本站提供的使用路线。

## 如何开始
建议从 README 的文件清单阅读：auth_flow.py 表示认证流程，mail_outlook.py 与 mail_cf.py 表示邮箱接入，webui 负责可视化管理。先区分配置、状态与敏感凭据的保存位置，再阅读错误分类和状态回收逻辑。README 的克隆示例仍使用 gpt-outlook-register 旧名称，核对当前仓库再引用路径。

## 一个使用示例
说明性研究示例，未执行：在纸面上用一条虚构任务描述“进入处理、等待邮箱结果、超时、归还可用状态”的过程，查阅各状态对应的代码职责，检查超时是否会把任务永久留在 in_use。预期产物是状态转换说明和待核查条件，不连接邮箱、不获取验证码、不创建账号。

## 注意事项与相关项目
README 中 token 复制、账号池和并发操作都涉及真实凭据；日志与导出文件需要按敏感资料处理。第三方认证流程会变化，仓库说明不能证明当前链路可用。这里没有复现注册、绕过风控、租用号码或运行任何账号自动化，内容仅归纳已读公开资料与离线阅读入口。
