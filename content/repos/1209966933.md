## 它是什么

REA 将软件分析工具封装为 MCP 与 CLI 工作流。代理提出分析任务，REA 返回模块、调用关系、位置和观察证据，代理再据此解释行为。它覆盖多种目标，但每种目标所需的宿主及分析引擎不同。

## 适合什么场景

- 对自己开发或获授权的 JavaScript/Electron 应用追踪模块和 IPC 边界。
- 分析自有二进制、网络抓包或运行日志，要求结论对应具体证据。
- 已有 Hopper、Ghidra 或 IDA 等环境，希望接入代理分析流程。

## 如何开始

1. 核对 README 的 Node.js 支持范围：22.x 至少 22.19、24.x 至少 24.11，或 26+；个别分析能力还有更高要求。
2. 按目标选择静态应用分析或原生分析引擎。需要代理接入时运行上游的 `npx rea-agents setup`，审阅配置修改后再确认。
3. 先使用一个已知结构的自有样本，检查结果中的证据位置和未知项。

## 一个使用示例

官方命令改写，未执行：分析自己构建并解包的 Electron 应用目录。

```sh
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/your-app --json
```

预期获得模块、导入关系和 Electron 边界等结构化结果。此命令会获取并执行第三方工具，示例路径必须替换；本文未安装或运行 REA。找到一个字符串不等于证实完整业务路径。

## 注意事项与相关项目

静态 JavaScript 和 .NET 路径与运行时捕获不同：后者可能启动或操作目标程序。原生分析还依赖引擎许可、平台和版本。仅分析自己拥有或获授权的软件；README 的 main 分支能力可能先于 npm 发布，实际使用应核对发行版本。
