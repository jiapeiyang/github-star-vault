## 它是什么
Humanizer 是一个可由支持 Skills 的编码助手读取的写作技能。它按问题强弱标记机械表达，先起草改写，再检查原始事实和残留文风，最后给出结果。当前 README 列出 25 种模式，包括先铺垫后表达、无必要的对比、机械三段式、夸张意义和聊天包装文字。

## 适合什么场景
适合整理技术文档、发布说明、参考文章或个人文章的草稿。提供两三段自己的文字样本时，还可要求匹配句子节奏与措辞。它处理表达方式；对原始资料真实性、引用是否支持结论等问题仍需要单独核查。

## 如何开始
使用 Skills CLI 时，官方入口是 `npx skills add blader/humanizer --global`；去掉 `--global` 则限定当前项目。重新加载后调用 `/humanizer`。Claude Code 2.1.142 及以后也提供插件安装方式，插件命令为 `/humanizer:humanizer`。可先粘贴短文，或者明确给出待改写文件路径，并声明文档类型和保留条件。

## 一个使用示例
官方流程改写，未执行：给助手“Humanize the prose in docs/launch-post.md”，再补充“保留版本号、代码和链接目标”。预期是正文更直接，同时 frontmatter、代码、数据与链接目标不被语言润色改动。粘贴文本时，上游约定会展示初稿、简短自评和最终稿，可以用这些中间结果检查是否改变了原意。

## 注意事项与相关项目
上游明确要求姓名、数字、日期和引文来自原文或作者；缺失细节应询问，不能凭空增补。被列为 weak alone 的模式不是见到就删除，作者有意使用的破折号、语气和个人观点也应保留。Humanizer-zh 是中文适配分支，便于中文内容使用，但不能以共同名称推断两者规则版本相同。
