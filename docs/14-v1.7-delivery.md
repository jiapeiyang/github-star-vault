## 已实现

- 首页增加本期封面；“收藏回顾”中可以切换每周特刊与原有时间线。
- 每期最多五个：一个主读、两个同主题延伸、两个不同领域的偶遇。主读提供四个重读问题和原文章节展开，能直接跳到完整解读的相应位置。
- 优先收藏满 90 天、有完整解读、仍在公开 Stars 且未归档的项目；八周内不重复，八个领域主题轮换。同等条件稳定打散，不按热度排名、不推断遗忘程度。
- 当期第一次生成后固定名单和编选依据；后续事实同步不重排。往期保留名单，解读继续使用最新资料，界面明确说明这一边界。
- 特刊详情链接带 issue 日期，支持刷新、章节定位、返回原期；可手动加入已有候选工具篮并带走全文资料。
- 只有实际生成的期刊进入档案。候选不足时少量出刊；无候选不造空期；失效引用显示记录占位；损坏的附加特刊数据不阻断项目库。
- 现有 GitHub Actions 已接入生成和校验步骤，源数据提交清单增加特刊档案。上线后复用既有定时流水线自动出刊；后续真实跨周生成仍需在下次成功执行时观察。

## 后续维护

- 人工主题：`config/weekly.json`。主题标题、导语和问题会复制到新期，不追改过去的标题。
- 名单档案：`data/weekly-issues.json`，只由 `python3 scripts/generate_weekly.py` 写入；不要手改来换掉已出刊名单。
- 本地顺序：生成特刊 → 校验 → 构建。普通 `npm run build` 只消费已有特刊，不根据运行时间生成新的名单。
- 自动出刊复用原来每日四次的同步流水线。北京时间跨周后，第一次成功生成、构建并部署才会上线；不保证周一零点立即出现。失败时保留原档案和上一期，不伪造新期。
- 本地预览：`http://127.0.0.1:4177/github-star-vault/?view=weekly`。交付时服务保留运行，开发服务与异常场景测试服务关闭。

## 我没有防什么

- 不判断用户是否读过、是否记住，不验证长期学习效果；没有浏览追踪、打卡、提醒邮件或个人阅读进度。
- 不替用户实际安装、执行或验收上游项目；来源变化继续提示，原文的未执行说明保留。
- 不保存解读和 README 的历史全文；往期名单固定，但正文和当前状态会更新。
- 不给并发 CI 加锁或自动重试；沿用 Git 推送冲突显式失败，避免覆盖他人的提交。未模拟 GitHub 托管平台的故障或实际定时发布。
- 没有多用户推荐、离线阅读或跨设备同步。候选工具篮继续沿用原来的标签页暂存边界。
- 不做整站跨浏览器兼容性认证；本轮完成的是当前内置浏览器中的桌面/窄屏与主流程验证。
