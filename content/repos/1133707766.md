## 它是什么
Multica 是可自托管的代理协作工作空间。用户把 issue 指派给一个已配置的代理，代理在受控 runtime 上调用本机编码 CLI，报告过程并把结果交回 review。问题意图、执行日志、决定和代码差异因此关联到同一任务，而不散落在多个终端会话里。

## 适合什么场景
适合同时使用 Claude Code、Codex 等工具，需要统一任务状态、运行成本和评审记录的个人或团队。它调度现有代理 CLI，并不内置替代模型；团队的运行机器、代码访问和提供方登录仍需事先准备。

## 如何开始
从官方网站登录或下载桌面版；桌面应用可把当前电脑注册成 runtime。先确保该机器至少安装并登录一个支持的代理 CLI。在 Runtimes 连接机器，再到 Agents 创建代理，选择 runtime 与 provider，最后创建 issue 并设其为 assignee。完全自托管路线另读 SELF_HOSTING.md，需要 Docker 等基础环境。

## 一个使用示例
官方入门流程改写，未执行：创建“为项目搜索增加空结果提示”的 issue，写明触发条件与验收标准，指派给已连接仓库的代理。查看执行日志和问题中的进度，等任务进入 review 后核对 diff 和验证证据。预期是可供人工审阅的实现结果，不是指派动作本身就意味着已合并发布。

## 注意事项与相关项目
Web、桌面、后台和本地 daemon 承担不同职责；模型调用和团队服务的数据流应按安全模型文档理解，不能仅凭“代码在本机”推断所有信息永不离机。聊天渠道中有社区维护的适配器，支持程度可能不同。README 说明 iOS 当前需源码构建，不能把它当作已上架应用。
