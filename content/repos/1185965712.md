## 它是什么
codex-provider-sync 针对切换 model_provider 后旧会话不再显示的问题，同步磁盘会话和 SQLite 索引中的 Provider 信息。它在写入前备份，不负责账号登录或切号，也不改 auth.json 与消息正文。恢复列表可见性与旧会话能否继续推理是两件事。

## 适合什么场景
适合从官方 OpenAI 切到自定义 Provider 后，确认数据仍在磁盘但列表看不到的情形。若两个入口共用同一 Provider ID，或切换工具已经同步历史，通常没有必要再做一次。应先诊断实际存储路径和状态。

## 如何开始
Node.js 16.20.2+ 可按 README 安装 `npm install -g @dailin521/codex-provider-sync`，先执行 `codex-provider status` 只读检查。需要图形界面时运行 `codex-provider web`，默认本机监听并配对浏览器。确认 Profile 和目标 Provider 后保留“仅同步元数据”，查看写入确认；SQLite 被占用时按文档关闭相关进程再处理。

## 一个使用示例
官方流程改写，未执行：切换 Provider 后，先读状态并确认旧 rollout 存在；选择当前 Provider 完成同步，再重启相应客户端检查历史条目。预期是 Provider 元数据对齐，恢复列表可见性。必要时可依据工具生成的备份目录恢复，本次没有触碰任何真实 Codex 存储。

## 注意事项与相关项目
跨 Provider 或账号时，后端可能不能解密 encrypted_content，继续对话或 compact 仍会失败；这不由元数据改写解决。CLI/Web 与 Windows GUI 分别发布，版本号不一定相同。自定义 sqlite_home、WSL 路径与活跃会话锁需要按实际配置核对。
