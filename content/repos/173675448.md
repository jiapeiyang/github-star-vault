## 它是什么
jsproxy 是一个在线网页代理实验：服务器主要转发流量，浏览器中的 Service Worker 拦截请求，配合注入的 JavaScript 对 URL 相关接口做适配。与完全在服务端替换 HTML、CSS、JavaScript 链接的代理相比，它把较多处理放在客户端。README 同时介绍 nginx 服务端、可独立托管的前端与 cf-worker 版本。

## 适合什么场景
适合研究网页镜像、Service Worker 请求处理及站点沙盒的兼容性；也能作为理解前后端代理职责的历史案例。它不是通用 VPN，不能据此认为所有应用、浏览器 API 或动态脚本都会透明兼容。

## 如何开始
先读“项目特点”了解 API 虚拟化边界，再选择 README 的手动安装文档或 cf-worker 目录。旧自动安装流程要求 Linux x64、root 权限，申请证书时 80 端口需可达。若独立托管前端，要在 conf.js 中配置 node_map 与 node_default，使前端指向自己控制的节点。

## 一个使用示例
说明性配置示例，未执行：在测试节点已经部署完成的前提下，把静态前端放到自己的站点，配置一个节点 ID 并设为默认，然后用不含账号的公开测试页检查图片、相对链接和跳转。预期浏览器请求通过所选节点转发；“打开首页”不能证明整个目标站点兼容。

## 注意事项与相关项目
README 主要记录 2019 年版本，v0.1.0 的网络接口与旧版不兼容，域名及证书示例也需重新核实。默认允许 github.io 站点调用可能带来流量消耗，上游提供 allowed-sites.conf 和内网访问限制说明。文档明确不建议在演示代理登录，代理节点能接触传输内容。
