## 它是什么
GitNexus 对代码仓库建立知识图，将依赖、调用链、聚类与执行流程提供给 MCP 工具和 Web UI。它侧重帮助代理查影响范围和结构关系，浏览器界面则支持快速探索仓库。图是源码索引与分析结果，不能替代运行时观察。

## 适合什么场景
适合改动跨多个模块、担心漏掉调用者，或想把架构关系交给编码助手查询的场景。小仓库可先试一个具体调用链；大仓库要考虑初始索引耗时、原生解析依赖与内存使用。

## 如何开始
README 快速入口为在仓库根运行 `npx gitnexus analyze`，再 `npx gitnexus setup` 连接编辑器。需先知道 analyze 不只是只读扫描：它还安装技能、注册 Hooks 并创建 AGENTS.md/CLAUDE.md 上下文文件。先检查现有规则和安装范围，建立索引后再在宿主使用 MCP 图查询。

## 一个使用示例
说明性示例，未执行：准备修改一个导出函数，先查询其调用链，查看图中哪些模块依赖它，再逐个打开关键调用点确认参数与返回值。预期得到一份影响范围候选清单，供实现和测试选择使用；动态分派与运行配置相关调用仍可能需要额外检查。

## 注意事项与相关项目
当前 README 标为 PolyForm Noncommercial，不能沿用早期印象把它当作无限制商用许可。索引会消耗内存，托管部署持有访问 token 的人可以读取已索引仓库，部署到外部不是默认无风险的试用。Understand Anything 也是图形理解工具，但结构解析与模型归纳分工应分别比较。
