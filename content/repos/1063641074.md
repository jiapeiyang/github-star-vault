## 它是什么
A2UI 让代理发送组件结构和数据模型，由客户端映射到自己的 Flutter、Angular、Lit 等组件。界面描述是 JSON 数据，不要求执行模型生成的任意代码；组件以 ID 引用，便于增量更新。

它解决的是代理与客户端之间“如何表达界面”，不是整套聊天产品。当前 README 标注稳定协议族 v0.9，v1.0 仍为候选版本，接入需匹配协议和渲染器。

## 适合什么场景
代理回答需要卡片、表单和选择操作；同一服务要在多个客户端呈现；希望限定模型只能组合批准的组件。

## 如何开始
先用 A2UI Composer 生成 JSON，或在 Theater 查看流式场景。端到端餐厅 Demo 需要 Node.js、Corepack、uv 与 Gemini API Key，按 Quickstart 启动 Lit 客户端和 ADK 代理。正式接入时先定义客户端组件目录，再核对消息与事件契约。

## 一个使用示例
官方 Restaurant Finder 场景改写，未执行：用户描述餐厅需求，代理返回候选卡片和可选操作，客户端以自己的卡片组件展示；用户选择后再回传事件更新界面。预期 UI 可增量变化，同时保持客户端控制的组件范围。

## 注意事项与相关项目
声明式数据仍需输入校验和业务权限控制，可信组件不能自动保证按钮操作安全。旧 v0.8 示例与新协议不应混用。它属于运行时界面协议，DESIGN.md 则描述视觉规范。
