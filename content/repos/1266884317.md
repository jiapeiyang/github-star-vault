## 它是什么
firstmate 是一套运行多名编码智能体的目录发行包：仓库中的指令、Skills、脚本、策略与状态约定，把普通终端编码宿主组织成一个负责沟通和监督的主代理。它通过可见的终端会话分配任务，并给工作代理建立隔离的 Git worktree。

仓库本身不是模型、独立桌面应用或一个需要运行 npm start 的服务。它的启动方式是克隆目录，然后在目录内开启受支持的编码宿主，由宿主读取相应规则。当前 README 介绍 tmux 默认后端，并连接 Herdr 等其他后端配置。

## 适合什么场景
多个仓库任务同时推进、需要看清每个任务在哪个会话运行时，这套约定可用于组织监督和交付。它也区分改代码的 ship 任务与调查型 scout 任务。只有一个简单改动时，引入这一整套目录、工作树和监督流程未必必要。

## 如何开始
1. 准备受支持的编码宿主、Git、已认证的 GitHub CLI，以及所选终端后端。
2. 阅读 README 的 Quick Start 与项目交付模式，明确使用本地交付还是 PR 流程。
3. 将发行目录与业务项目分开，按官方方式克隆并进入目录。
4. 启动选定宿主后，再描述项目、任务范围及允许的交付动作。

```shell
git clone https://github.com/kunchenguid/firstmate
cd firstmate
claude
```

## 一个使用示例
向已启动的主代理提出：检查某项目的间歇性登录测试，并另行调查深色模式的实现范围。要求调查给出报告、修复在隔离工作树内完成，并在允许的交付模式下展示差异和检查结果。

预期在所选后端看到独立工作会话，由主代理汇总结果。此例依据 README 中多任务演示改写，本站未安装发行包、启动工作代理或创建 PR。

## 注意事项与相关项目
不同宿主的监督唤醒机制不同，上游声明的支持不等于所有组合行为一致。规则中的自动合并、远程 secondmate 或消息 Relay 都有独立配置与影响，不应因普通本地任务而默认启用。已有 Herdr 等工作流时，应先评估衔接方式；本项目的价值是任务组织约定，而非要求替换所有终端工具。
