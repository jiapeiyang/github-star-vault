## 它是什么
fex-team/interview-questions 描述团队的面试思路，区分项目经历、基础知识、技术深度、视野与主动性。许多问题是开放式追问，例如如何设计组件、解释性能优化原理、复盘技术问题，重点在判断过程与实际经验，而不是一套带标准答案的题库。

## 适合什么场景
适合整理真实项目经历、准备讨论设计取舍，或借鉴技术面试如何从现象追到原因。对于希望背诵简答的需求，它提供的价值有限；问题需要基于本人做过的工作回答。

## 如何开始
直接阅读 README。先挑一两个真实项目，按背景、角色、问题、解决方式和效果组织材料，再看技术一面和二面的追问。遇到组件设计题，写清调用接口、状态和异常情况；无需安装或运行本仓库。

## 一个使用示例
官方问题改写，未执行面试：选择一个自己实际做过的 Dialog，说明打开关闭接口、焦点与键盘行为、遮罩和内容滚动如何处理，再解释遇到过什么问题以及如何验证修复。预期形成可追问的设计说明；不能补写未做过的规模、指标或职责来凑完整经历。

## 注意事项与相关项目
面试轮次、招聘邮箱和团队技术栈是 README 的历史信息，不表示当前仍在招聘或流程未变。比如文中 PHP 与 jQuery 的时代背景，应与今天岗位说明区分。这里仅提供资料入口和准备方式，没有投递简历或联系团队。
